# Fixes

1. **Forked migration chain** — `alembic/versions/c1d2e3f4a5b6_add_server_name_to_benchmark_results.py`: `down_revision` pointed at `f0e43419bf9b` (the initial schema), so the chain had two heads. Its own docstring says it revises `b1c2d3e4f5a6`, so I set it back to that. The chain is linear again.
2. **Column declared in the model but never created** — `BenchmarkResult.mean_itl_ms` was in the ORM model with no revision creating it, so every leaderboard SELECT returned 500 on the real database. I added `alembic/versions/c4d5e6f7a8b9_add_mean_itl_ms_to_benchmark_results.py`, a nullable float column with a downgrade, and applied it to the live DB with `alembic upgrade head`.
3. **Ingest upsert used the wrong conflict target** — `app/routers/ingest.py`: `ON CONFLICT (run_id)` matches no unique constraint, so every ingest returned 500. I changed it to `(run_id, sub_run_index)`, which is `uq_benchmark_run_sub` and what the contract specifies.
4. **Ingest did not lowercase classification fields** — `app/routers/ingest.py`: `gpu_type="H100"` broke the `ck_gpu_type_lower` check constraint. `gpu_type`, `model_name` and `precision` are now lowercased before insert.
5. **Hidden leaderboard filter** — `app/routers/results.py` `_build_filter_conditions` always added `server_name IS NOT NULL`, which hid every run ingested without a server name, including the e2e run. The contract says all filters are optional, so I removed it.
6. **IP mask kept three octets** — `app/schemas/benchmark.py` `_IP_RE` captured three octets, giving `10.6.12.x.x`. It now captures two (`10.6.x.x`), matching `app/utils/sse.py` and the docs. Detail sub-runs (`BenchmarkDetailSubRun`) now mask IPs as well; before, they returned them raw.
7. **Catalog seeder did not update `image_tag`** — `app/services/catalog_seeder.py`: when re-seeding an existing workload type, `image_tag` is now refreshed along with display_name and description.
8. **LLM benchmark command had been gutted** — `app/services/manifest_builder.py` `build_llm_benchmark_command`: it hardcoded `vllm/vllm-openai:latest` and had dropped the node-env prelude, the HF_TOKEN passthrough, the `NODE_RESULTS_PATH:/results` mount, the dataset mount and the `--tp` argument. All are restored. The image is now the registry's `llminference:<tag>`, using the workload_types tag or falling back to `WORKLOAD_IMAGE_TAG`.
